# Deviations from the v1.0 specification manifest

`DOSSIER_MANIFEST.json` lists the 17 files of the specification package and their SHA-256. The original version remains available in commit `b019989` (`git show b019989:<path>`).

`npm run check:spec` recomputes the hashes. Each declared deviation carries **two** hashes: the manifest one (`manifestSha256`) and the one of the current accepted content (`currentSha256`). The check fails:
- on any undeclared deviation;
- on any later modification of an already declared file (`MODIFIÉ`);
- on an invalid declaration (file outside the manifest, wrong original hash, missing reason);
- on a stale declaration (the file has become identical to the spec again).

The v1.0 manifest itself is never modified.

## Arbitrated point

`CLAUDE.md` required updating `docs/09_DECISIONS_ET_RISQUES.md` on every change of assumption, which broke the traceability of the spec. **Owner decision (2026-11-03)**: the v1.0 manifest remains immutable, the implementation journal is `docs/implementation/JOURNAL_DECISIONS.md`, and the `CLAUDE.md` instruction is corrected (deviation declared above).

## Hardening of the check (batch P5)

Before batch P5, only the original hash of a deviation was checked: a second modification of `.gitignore` would have gone unnoticed. This is fixed with `currentSha256`. Negative test run: a line added to `.gitignore` makes the check exit with `MODIFIÉ`, code 1.
